# 墨校台 MVP2「智校流」设计

## 定位

MVP2 把墨校台从“本地编校与出版工具”扩展为“人机协同、证据可追溯的文学编辑工作台”。AI 不是聊天入口，也不拥有母本写权限；它只生产结构化建议，建议必须进入收件箱，经作者或编辑逐条接受后才转化为普通母本修订。

## 产品闭环

1. 用户选择单篇或当前筛选范围，明确看到将被检查的内容范围。
2. 本地检查器离线生成结构、体裁、系年和笺读一致性建议；可选的 OpenAI-compatible BYOK 连接器只在用户主动触发后发送预览范围内的内容。
3. 每条建议保存任务类型、原值、建议值、理由、置信度、证据、输入哈希、模型与时间。
4. 用户逐条接受、拒绝或保留；接受动作通过既有工作区事务写入，拒绝不会改变母本。
5. 批量文本先解析为暂存预览，用户确认篇目边界、标题和体裁后才入库。

## UI

主导航收敛为真实可用的“文库、智校、版本、出版”。智校工作台采用编辑案卷视觉：左侧是运行范围与隐私边界，中间是建议队列，右侧显示原值/建议值差异与依据。高置信度不等于自动接受；颜色只表达状态，不表达真伪。版本中心展示不可变语义版本并允许确认后恢复。`⌘K` 真正聚焦文库搜索。

## 安全与失败

- 默认只运行本地规则，不联网。
- 云端密钥由 Electron `safeStorage` 加密后写入权限 `0600` 的本机凭据文件，绝不进入 SQLite、导出包、日志或仓库。
- 远端端点仅允许 HTTPS，另允许用户明确选择的 localhost；响应必须通过结构校验。
- 网络失败、模型格式错误或密钥缺失只终止本次运行，不产生部分母本修改。
- 审计记录保存输入哈希和任务摘要，不复制完整正文。

## 验收

单元测试覆盖建议生成、响应校验、字段白名单、接受/拒绝状态和批量预览；存储测试覆盖建议运行持久化；Electron E2E 覆盖本地扫描、接受建议、重载持久化、批量预览后入库、版本查看与恢复，以及深色窄屏。
