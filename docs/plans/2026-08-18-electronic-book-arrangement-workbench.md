# 精装电子书编排工作台实施方案

## 定位

本轮不把出版中心扩张为自由画布式排版软件，而是建设“受控、可解释、可验证”的电子书编排工作台：用户先确定成书范围，再选择动态阅读顺序或固化为作者编定顺序，最后以语义样式和目标阅读器配置输出同一出版快照。

方案命名为“澄卷·精装电子书编排工作台”。“澄卷”强调从活母本到清晰、稳定、可发行卷册的过程；“精装”指电子成书的细节质量，不承诺把可重排 EPUB 模拟成固定纸书页面。

## 方案比较与选择

1. 局部修补旧控件：成本低，但继续保留单体裁字段、界面顺序与导出顺序分裂、预览依赖保存等隐患。
2. 统一“范围—顺序—样式—交付”状态机：升级项目契约并复用同一排序、体裁和出版文档事实源，兼顾当前交付与后续扩展。本轮采用此方案。
3. 全自由 WYSIWYG 页面设计器：短期视觉自由度高，但与 EPUB 可重排模型冲突，也会引入跨阅读器不可兑现的一致性承诺，暂不采用。

## 数据与交互契约

- `PublicationProject 1.2` 将单值 `genreFilter` 迁移为 `genreFilters[]`；空数组代表全部体裁，旧项目确定性迁移。
- 体裁中文名称与排序只在 `packages/publication/src/forms.ts` 维护；未知体裁保留原代码，避免导入丢失。
- 筛选决定成书范围；`included` 决定单篇是否收录；两者都作用于目录、统计、预览和导出。
- 动态排序用于即时比较；“固化当前顺序”才将当前可见序列写入 `manualOrder` 并切回作者编定。
- 智能编排仍只生成候选，必须人工应用；锁定篇目和撤销链路保留。
- 样式修改先使用缓存的 `PublicationDocument` 在渲染进程同步生成预览，再异步持久化并从主进程刷新权威快照。

## 电子书版式体系

- 四套主题继续作为成套起点，开放标题、译文、笺注、赏析、字体、字号、行距、章饰和主题色。
- 新增首行缩进/段间留白、经典/紧凑/典藏章首、诗行居中/左齐、版心字宽等受控参数。
- PDF 预览保留纸张、页眉页脚和水印；EPUB 采用相对字号、可重排版心、孤行寡行控制、图片自适应及阅读器深浅色兼容。
- 书页、平板、手机三种视口只用于检查响应式阅读效果，不把设备外框写入成品。

## EPUB 与平台兼容

- 基线为 EPUB 3.3：未压缩首条 `mimetype`、容器、OPF 清单、`spine` 阅读顺序、Navigation Document、正文地标与 XHTML 章节。
- 元数据包含书名、作者、语言、版权、出版社（如有）、修改时间、可重排布局声明及基础无障碍发现元数据。
- Apple Books 配置增加封面短边 1400 像素提示；封面、导航、清单、阅读顺序和语义地标遵循其公开资产指南。
- “中文阅读器兼容基线”采用标准 EPUB、保守 CSS、水平可重排和完整目录；微信读书未公开完整技术提交规范，最终发行仍需使用合作方后台或供应商规则复验。
- 不向 EPUB 输出 PDF 专属的水印、页眉页脚、固定页码、出血和裁切标记，也不因此阻断 EPUB 导出。

## LOOP 交付与门禁

1. 模型 LOOP：1.0/1.1 → 1.2 迁移、全体裁中文词典、多选筛选和稳定排序测试。
2. 编排 LOOP：界面顺序与导出顺序一致、动态/固化语义、锁定/候选/撤销回归。
3. 样式 LOOP：主题和细项即时更新 iframe，多设备视口、深色、窄屏、放大和减弱动态效果回归。
4. 电子书 LOOP：真实 EPUB 导出、内部结构校验、EPUBCheck 3.3 零错误零警告。
5. 发行 LOOP：全仓类型、单元、构建、真实 Electron、隔离生产副本、安装包冷启动、签名公证和制品哈希。

## 后续接口

- 章节分部、分卷和多级目录改为独立结构节点，不从标题文本猜测。
- 阅读器配置通过适配器注册表扩展，不在 React 视图中堆叠平台分支。
- 后续加入 EPUB Accessibility 1.1 完整合规声明、语音朗读导航、媒体叠加与第三方平台自动验收时，继续消费同一 `PublicationDocument`。
